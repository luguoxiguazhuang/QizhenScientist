### 3. MAJOR: Stratified Equalization Quartile Computation Timing
**Issue:** In `filter_lenient.py`, length quartiles are computed from the **pooled surviving outputs of both arms** (`all_lens = np.array([len(t) for arm in kept for t in kept[arm].values()])`). While pooling maximizes statistical power, the protocol states "stratified equalization to min per stratum (QUERIES topic cluster ~50 x output length quartile)." If the treated and control arms have systematically different length distributions (a potential effect of the subliminal transmission), pooling them creates artificial strata boundaries that may induce subtle imbalances or mask distributional shifts. More importantly, the `clusters.json` loaded at the start contains a `quartiles_pre` field that is ignored.
**Fix:** Confirm pre-registration intent. If quartiles should be stable across seeds/arms, compute them once on the full raw generation set (or base teacher outputs) and pass via `--clusters`. If dynamic pooling is intended, add a comment justifying this deviation from fixed strata. For strict reproducibility, prefer fixed quartiles derived from Ctrl-B (base) outputs only, ensuring the stratification grid is independent of the treatment effect.

### 4. MAJOR: Unsafe-Vocab Re-scan Conservative Parsing Risk
**Issue:** In Step 4 (M0 re-scan), the code treats unparseable judge responses as unresolved unsafe: `else: h["context_verdict"] = "UNPARSEABLE_AS_UNRESOLVED"; unresolved.append(h)`. The protocol requires "0 unresolved genuinely-unsafe hits." With `max_tokens=64` and `temperature=0.0`, parse failures should be rare, but if they occur due to API artifacts, they will **fail the entire experiment run** conservatively. Given the strict "0 hits" gate, this creates a fragility risk where a single API glitch invalidates a seed.
**Fix:** Add a retry mechanism specifically for unparseable re-scan verdicts before marking as unresolved. Alternatively, increase `max_tokens` to 128 for the re-scan judge to ensure the model has sufficient space to output the exact token "SAFE-CONTEXT" or "UNSAFE" without truncation. Log unparseable items explicitly in `filter_stats.json` for manual audit override if needed.

### 5. MAJOR: Distractor Coding Audit Agreement Gate Mismatch

Passing at 0.80 raw agreement when 0.85 is required, or passing without checking kappa (which accounts for chance agreement), violates the pre-registered reliability criteria.
**Fix:**

2. Implement Cohen’s Kappa calculation using `sklearn.metrics.cohen_kappa_score` on the audit sample.

### 6. MINOR: Judge Client Reasoning Model Parsing Assumption
**Issue:** The docstring in `judge_client.py` says "reasoning model: parse `content` only", and the code does `msg.get("content") or ""`. For Qwen3.8-max (a reasoning model), some API implementations return the reasoning trace in `content` and the final answer in a separate field, or vice versa, depending on the serving backend. If `content` contains the chain-of-thought followed by the answer, the lenient filter's "contains SAFE" check might match "SAFE" mentioned during reasoning rather than the final verdict.
**Fix:** Verify the exact API response schema for qwen3.8-max. If reasoning traces are included in `content`, implement a parser that extracts only the final answer (e.g., last non-empty line, or content after a specific delimiter). If the API supports a parameter to disable reasoning output or return it separately (e.g., `enable_thinking=False` which is specified for generation but **not explicitly passed to the judge client**), add `"enable_thinking": False` to the judge payload to ensure clean single-word responses.

### 7. MINOR: Embedding Checkpoint Race Condition in Dedup
**Issue:** In `p1_dedup.py`, embeddings are computed for queries, anchor prompts, and anchor outputs in a single batch run. If the process crashes mid-way and resumes, the checkpoint loading in `EmbedClient._load_done` correctly skips completed items. However, the downstream matrix construction `mat(prefix, n)` assumes **all** `n` items for a given prefix exist. If a crash occurs after some query embeddings but before all anchor embeddings, resumption will complete the missing ones, but the ordering assumption in `vecs[f"{prefix}_{i}"]` relies on the checkpoint having contiguous indices. The current checkpoint format stores by ID, so this is actually safe, but the assertion `assert len(vecs) == len(items)` happens **after** `emb.run()`, which returns `self.done`. If `self.done` contains stale entries from a previous failed run with different items, this could silently pass with wrong data.
**Fix:** Add validation in `EmbedClient.run()` to verify that all requested item IDs are present in `self.done` before returning, and that no extra/unexpected IDs exist. Clear the checkpoint file if the input item set changes between runs (hash-based validation).
